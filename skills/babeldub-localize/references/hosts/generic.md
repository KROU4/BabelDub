# Хост: веб-чаты и прочие агенты

Читай, если ты работаешь в веб-чате (claude.ai, Claude Desktop без доступа к файлам, ChatGPT web, Custom GPT) или в агенте, для которого нет отдельного файла (Cursor, OpenCode, GitHub Copilot и другие).

## 1. Агенты с доступом к оболочке (Cursor, OpenCode, Copilot CLI и др.)

- Установка скиллов: `npx skills add KROU4/BabelDub` (флаг `-a <агент>` или `-g` для всех проектов пользователя).
- Работай как в Codex (`references/hosts/codex.md`): команды `babeldub` в оболочке, роли выполняешь сам в основной сессии по `references/roles/*.md`, перевод по одному пакету.
- `${CLAUDE_PLUGIN_ROOT}` не подставляется; пути в скиллах относительны к папке скилла.

## 2. Веб-чаты: только перевод пакетов

В веб-чате скилл работает в облачной песочнице: **нет GPU, нет доступа к папке игры и к `BABELDUB_HOME` пользователя**. Озвучка, извлечение и сборка там невозможны. Возможна одна стадия — перевод пакетов, которые пользователь выгрузил со своей машины.

Скажи это пользователю сразу, одной фразой, и предложи один из путей:

- **Полный дубляж:** поставить BabelDub в локального агента (Claude Code, Codex, Gemini CLI) — команды установки в соответствующих файлах `references/hosts/`.
- **Только перевод в чате:** пользователь сам ведёт CLI на своей машине, а в чат приносит пакеты.

### Порядок «только перевод»

На машине пользователя (он выполняет сам):

1. `babeldub init "<папка игры>" --lang <код>`, затем `scan`, `extract`, `link`, `cast`, `cast select`, `translate plan`.
2. `babeldub batch make`, затем `babeldub batch next` — команда покажет пути `in` и `out` пакета.
3. Загрузить в чат файл `translate/batches/<bid>.in.jsonl`, а также `translate/style_bible.md` и `translate/glossary.agent.jsonl`, если они есть.

В чате (делаешь ты):

1. Прочитай `references/roles/translator.md` и переведи пакет по его правилам: эмоциональная форма оригинала, бюджет слогов, плейсхолдеры, глоссарий, `dub_text` и короткие `variants`.
2. Если глоссария и style bible нет, сначала выполни сокращённую роль lexicon (`references/roles/lexicon.md`) по самому пакету: имена и термины пакета, «ты/вы» сцены. Результат отдай пользователю файлами, чтобы он положил их в `translate/`.
3. Верни файл `<bid>.out.jsonl`: по одному JSON-объекту на строку, те же `id`, UTF-8 без BOM. Если в чате можно создать файл для скачивания, создай его; если нельзя, выведи содержимое одним блоком кода без пояснений внутри.
4. Число объектов должно совпадать с числом реплик в пакете (без строки-заголовка).

Снова на машине пользователя:

1. Сохранить ответ как `translate/batches/<bid>.out.jsonl` в папке проекта (путь `out` из `batch next`).
2. `babeldub batch submit <bid>`. Код 2 или 3 — принести в чат `errors[]` или `over_budget[]` из вывода; ты исправляешь и возвращаешь файл заново.
3. Следующий пакет: `babeldub batch next`.

Озвучку (`synth`, `post`, `qa`) и сборку пользователь запускает локально или через локального агента.

### Ограничения веб-чатов

- Длинные пакеты могут не поместиться в одно сообщение: проси пакеты по 40–60 реплик (`babeldub batch make --size 40`).
- Не обещай озвучку в чате и не имитируй вывод CLI.
- Не проси у пользователя файлы игры: в чат нужны только пакеты и глоссарий.
